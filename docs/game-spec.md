## 1. 作るもの（概要）

- タイトル：**熊のFP探し**
- ジャンル：ターン制ローグライク（『風来のシレン』のゲームボーイ・ファミコン期の内容を踏襲。システムは当時相当の素朴さで良いが、**見た目・名称・デザインはすべてオリジナルに変える**こと。シレンの固有名詞・グラフィック・音楽・キャラクターは一切流用しない）
- 世界観：主人公の熊が、FP（ファーストパートナー）を探すため、どこまでも深いダンジョンの最奥を目指す。だがダンジョンに底はなく、FPはなかなか見つからない。
- 競うもの：**ダンジョンの最深到達階**（詳細は §5.1）
- 音声：**一切なし**。BGM・効果音・Web Audio APIを実装しないこと。
- 公開先：Codeberg Pages を想定。サーバ処理なしの静的1ファイルで完結させる。

## 2. 技術選定（確定事項）

- 使用技術：**Vanilla JavaScript + HTML5 Canvas 2D + HTML + CSS**
- 選定理由：ターン制グリッドゲームのため物理演算やシーン管理ライブラリが不要であること、外部CDN依存を無くし単一ファイルで配信できること、iPhone SE級の端末でも軽量に動くこと。
- 禁止事項：
  - 外部JSライブラリ・フレームワークの導入（Supabaseクライアントを除く。Supabaseは公式CDNのsupabase-js読み込み、またはRESTを直接fetchするかのどちらかとし、採用した方式を報告すること）
  - ビルド工程（バンドラ、トランスパイラ）の導入
  - 画像・音声などの外部アセットファイル。グラフィックはCanvas描画、CSS、絵文字、またはコード内に埋め込んだデータで完結させる。
- ファイル構成：HTML・CSS・JavaScriptを `index.html` 1ファイルにまとめる。

## 3. 対応端末・表示要件

- 必須対応：**iPhone SE（第2/第3世代、CSS表示領域 375×667px）のSafari** で快適に遊べること。これを満たした上で、一般的なスマホ・PCブラウザでも動くこと。
- 縦持ち（ポートレート）専用。横持ち時は「縦にしてください」という案内を表示して良い。
- 横スクロールを一切出さない。
- ゲーム中は、長押しメニュー、テキスト選択、ダブルタップ拡大、不要なページスクロールを抑止する。
- ピンチズーム：**禁止する**（`viewport` と `touch-action` で抑止）。これはゲーム仕様として明記された決定事項である。
- すべての操作ボタンは最小 44×44px 以上のタップ領域を確保する。
- セーフエリア（ノッチ・ホームバー）を考慮し、`env(safe-area-inset-*)` でUIが隠れないようにする。
- 60fpsを要求しない。ターン制のため描画は操作時の再描画＋軽いアニメーションで良いが、操作への反応は体感で遅延なく行うこと。

## 5. ゲームルール中核

### 5.1 スコア定義（重要・確定事項）
- ダンジョンは**エンドレス構造**とし、最下層は存在しない。各フロアに必ず1つ「下り階段」があり、降りるほど敵が強くなる。
- **スコア＝そのプレイで到達した最も深い階の数値**（B1Fで終了なら1、B12Fまで降りたなら12）。
- 到達階は「下り階段を降りて次のフロアに足を踏み入れた時点」で更新される。
- 主人公が死亡、または「あきらめる」を選んだ時点でゲーム終了。どちらの場合も、その時点の最深到達階を最終スコアとする。
- 同スコア時の順位付け（タイブレーク）：先に記録した方（`created_at` が早い方）が上位。
- 途中セーブ・中断復帰は実装しない（ページを閉じたらそのプレイは終わり）。これはv1の確定仕様。

### 5.2 深さによる難易度上昇
- 敵の種類は §8.3 の出現階テーブルに従う。
- **16階以深**は、出現テーブル最深帯の敵（ねむりヘビ、ぬしのイノシシ）を使い、HP・攻撃力・防御力・獲得経験値を基礎値 ×(1 + 0.1 × (現在の階 − 15))（端数切り上げ）に補正する。深く潜るほど際限なく強くなる。
- 罠の設置数は1フロア2〜4個を基本とし、6階深くなるごとに+1（フロアあたり上限8個）。

### 5.3 ゲームオーバー・終了
- HPが0になったら死亡。所持品・レベルはすべて失われ、結果画面へ。
- メニューの「あきらめる」（確認ダイアログ付き）でも終了できる。この場合もスコアは記録・送信の対象とする。
- 「もう一度」でも名前入力画面を経由し、保存済みの名前を表示する。空欄では新規プレイを開始できない。

## 6. ダンジョン仕様

### 6.1 フロア生成
- 1フロア＝**32×20タイル**のグリッド。
- 生成方式：フロアを格子状に区切り、4〜7個の矩形の部屋（最小3×3、最大8×6）を配置し、通路で全部屋を連結する。到達不能な部屋を作らないこと（連結性を必ず検証する）。
- 各フロアに必ず1つ「下り階段」を配置する。
- プレイヤー初期位置と階段は別の部屋に置く。
- アイテム：1フロアに2〜4個を部屋内のランダム位置に配置。
- 敵：フロア開始時に3〜5体。その後、20ターンごとに1体を画面外の部屋に追加湧きさせる（フロア内同時上限10体）。
- 罠：§5.2 の数（踏むまで不可視）。

### 6.2 視界とマップ
- 部屋の中では部屋全体が見える。通路では周囲1タイルのみ見える（初代シレン準拠の簡易視界）。
- 画面右上に簡易ミニマップを表示（踏破済みの部屋・通路、階段、自分の位置のみ。敵とアイテムはミニマップに出さない）。
- カメラはプレイヤー中心。タイルは1辺32論理pxで描画し、iPhone SEで約11×13タイルが視界に入るよう調整する。

## 7. ターン制ルールと操作

### 7.1 ターンの流れ
1. プレイヤーが1行動（移動／攻撃／アイテム使用／足踏み）する。
2. 全敵が1行動する。
3. ターン経過処理（満腹度減少、自然回復、状態異常の継続処理、追加湧きカウント）。

### 7.2 移動・攻撃
- 8方向移動（斜め含む）。壁の角を斜めにすり抜けることはできない。
- 敵に隣接した方向へ攻撃ボタンで通常攻撃。攻撃は向いている方向の1マスのみ。
- ダメージ式：`max(1, 攻撃側の攻撃力 − 防御側の防御力 + 乱数(−1〜+1))`
- 攻撃力＝基礎攻撃力（レベル依存）＋武器補正。防御力＝基礎防御力＋盾補正。

### 7.3 タッチ操作（iPhone SE前提・確定事項）
- 画面下部に操作エリアを常設する：
  - 左：**8方向バーチャルパッド**（3×3配置。中央は無効。各方向44×44px以上）
  - 右：**攻撃ボタン**（直前に向いた方向へ攻撃）、**足踏みボタン**（その場で1ターン消費）、**メニューボタン**
- バーチャルパッドは長押しで連続移動（160ms間隔程度）に対応する。
- ゲーム盤面へのタップ移動・スワイプ移動は実装しない（誤操作防止のため）。
- PC向けに矢印キー＋テンキー（8方向）、Zで攻撃、Xで足踏み、Mでメニューも対応してよい（必須ではない）。

### 7.4 メニュー
- メニューボタンで開く。項目：持ち物（使う／置く）、装備確認、現在の状態（HP・満腹度・現在の階・レベル）、あきらめる（確認ダイアログ付き。§5.3）。
- メニュー表示中はターンが進まない。

## 9. ランキング仕様（Supabase・リポジトリ準拠・必須）

### 9.1 基本方針（リポジトリの定めをそのまま適用）
- ランキングはSupabase連携を基本とする。
- **Publishable key（anon key）とプロジェクトURLは公開HTMLに記載してよい。**
- **service_role key、DBパスワード、秘密鍵は絶対にクライアント側へ入れない。**
- スコア送信は**二重送信を防ぐ**（送信開始でボタンを無効化し、送信済みフラグを立てる。同一プレイの結果は1回しか送れない）。
- 送信中・成功・失敗の3状態を画面に明示する。失敗時のみ「再試行」ボタンを出す。
- セットアップ用SQLは**ファイルにせず、チャットへコピペできる形式で提示する**。
- `templates/` のランキング対応HTML雛形が存在する場合、送信処理・表示処理はその雛形の作法に合わせること。

### 9.2 テーブル定義（案。雛形に既定の共通スキーマがある場合はそちらを優先し、差分を報告すること）
- テーブル名：`kuma_fp_scores`
- 列：
  - `id`：bigint、自動採番、主キー
  - `player_name`：text、必須（クライアント側で1〜10文字に制限。サーバ側でも `char_length` チェック制約を付ける）
  - `score`：integer、必須、**1以上（最深到達階。B1F開始のため最低1）**
  - `created_at`：timestamptz、既定値 `now()`
- RLS（行レベルセキュリティ）を有効化し、ポリシーは「匿名のINSERT許可」「全員のSELECT許可」のみ。UPDATE・DELETEは許可しない。

### 9.3 送信フロー
1. 結果画面表示と同時に自動送信は**しない**。「ランキングに登録」ボタンの明示タップで送信する。
2. タップ直後にボタンを無効化し「送信中…」を表示。
3. 成功：「送信しました」を表示し、ランキング表示を最新化する。
4. 失敗：「送信に失敗しました」と再試行ボタンを表示。再試行も二重送信防止の対象とする。
5. B1Fで終了した場合（score=1）でも送信可能とする。

### 9.4 ランキング表示
- 結果画面の下部に、`score` 降順 → `created_at` 昇順で**上位10件**を表示（順位・名前・到達階。到達階は「B12F」の形式で表示）。
- 自分が今回送信した記録が上位10件に入っていない場合、欄外に「あなた：◯位」を表示する。
- 取得失敗時は「ランキングを取得できませんでした」と表示し、ゲーム本体の動作は妨げない。

### 9.5 実験場連携
- 公開時は、ゲーム本体に加えて、Supabase設定、実験場トップ、詳細ランキングページの確認が必要（リポジトリの定め）。
- 実験場トップに `GAMES` 固定配列がある場合、Supabase登録だけでは一覧に表示されないため、**配列への追加が必要であることを納品時に必ず報告すること**（配列の編集自体は依頼者側の作業）。

- ドット絵風・レトロ調のオリジナルデザインとする。シレンを含む既存作品のグラフィック・名称・ロゴを模倣、流用しない。

- HUD（常時表示）：現在の階（例「B3F」）、HP（数値＋バー）、満腹度（数値）、レベル。
- メッセージログ：画面下部の操作エリア直上に直近2〜3行を表示（攻撃結果、拾得、警告、階の移動など）。
